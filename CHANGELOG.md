# Changelog

## 0.3.0

Adds a second backend that works **next to** the existing HTTP path: the host's own `re.sql` provider (PostgreSQL or SQLite).
The public contract is unchanged: same exports (`Call`, `TakeResult`), same operations, request and result bodies, error codes,
schema hash and receipt fingerprint, so consumers and lt-core's `LtDatabase` adapter keep working without changes.

- `vfs/database.json` gets `backend` (`"http"` default, or `"sql"`), `sqlAlias`, `sqlDialect` and `destructiveMode`. Existing files work as before.
- New SQL backend: `health`, `schema.sync` (hash, diff, dry run, repairs, destructive modes, SQLite table rebuilds), `schema.describe`,
  `insert`, `find`, `count`, `update`, `upsert`, `delete`, `flush`, `mutation.execute` and `mutation.receipt` with atomic receipts,
  in-memory idempotency keys, and stable error codes without driver messages.
- The HTTP code moved unchanged into `HttpBackend`; `DbClient` keeps tickets, results and the namespace check.
- `MiniJson.Parse` has a strict mode (duplicate keys are errors) used by the receipt validation.
- Requires **replay.blackice SDK 1.3.0**; the target server must be a 1.3.0 host for either backend.
- Tests: 100+ unit tests, including vectors generated by the real lt-database-api code and the generated SQL executed on SQLite.
- New guide: [docs/SQL-BACKEND.md](docs/SQL-BACKEND.md). Runtime-verified on a BlackICE server (Docker) with the smoke bundle: 38/38 steps on a SQLite alias and 38/38 on PostgreSQL 17.
  The host's SQLite sandbox does not authorize `pragma_table_info`; column names are read from an empty `SELECT` instead.
- The smoke bundle takes an optional connector bundle name (`db-smoke <label> [connector-bundle]`); a label containing `sql` expects the sql-mode refusal of an unfiltered delete (`filter_required`, no key permissions).

## 0.2.0

The bundle identity is `lt_database`, with `LtDatabase` contracts, `LtDatabaseClient` consumer helpers and `lt-db-*`
console commands. All examples, configuration guides and package filenames use this identity.

Update the helper and shared source references in consumers together, rebuild consumers, install the connector under
`lt_database`, and start it before consumer bundles. This is a breaking source and bundle-name change; the HTTP protocol
and database namespaces are unchanged.

## 0.1.0

Initial public lt_database release: signed BlackICE database connector, schema/query builders, consumer helper and
compiled recipes. Supports PostgreSQL, MySQL and MongoDB through lt-database-api. The helper includes `Db.IsQueued`,
`Db.Flush` and `immediate: true` for the API's optional write-behind mode.

Includes installation, configuration, usage, reference, operations, security and build guides; a documented 38-step
runtime smoke bundle; CI that compiles all three WASM projects; and an allow-listed ZIP packager with SHA-256 checksums.

The installed folder is `lt_database` and the namespaces are `LtDatabase` / `LtDatabaseClient`.
